## Evidence that the method is unchanged

The preliminary script (`legacy/ro1_preliminary/incentia_ro1_prelim.py`, `--local-root` mode) was run on
the same downloaded files as the new pipeline and compared patient by patient
(`scripts/s04c_compare_legacy.py`). For all 298 analysable patients, at thresholds 10%, 20% and 30%, the
interval counts and removed counts in all four classes (PAC coupling, pause after PAC, PVC coupling,
normal) are identical, as are analysed hours, PAC count, longest PAC run and Binici ESVEA status.
Total differences: 0. Evidence: `results/p0_legacy_vs_new.txt`.

Before that comparison the new pipeline was aligned with the preliminary script on the six points that
runbook T2 lists: the filter warm-up (the first five intervals of a segment are accepted untested), the
filter running per segment, overlapping interval categories, strict 0.2 to 3.0 s bounds with Q exclusion,
analysed hours as first to last non-Q beat, and the two dropped patients.

## Cause

The input data differ from those of the original run. Against the counts printed in Table 4.2, today's
files contain more intervals in every class: +11,621 normal, +527 PVC coupling, +7 PAC coupling and
+7 pause after PAC. Interval counts are fixed before any filtering, so no filter setting can produce them.

The specific cause is **unresolved**. No original downloaded P0 files, per-patient outputs
(`patients.csv`, `retention_by_patient.csv`) or run log exist on this machine, so the files of the
original run cannot be compared with today's. What is known:

* The original environment recorded wfdb 4.3.1, the version used today (`results/p0_environment.txt`),
  so a reader difference is unlikely.
* The preliminary script by default streams each annotation from PhysioNet and treats any read error as
  the end of that patient's segments, without logging (`load_segment` returns None on any exception). A
  streamed read failed in the same environment during a later header check (59 of 60 read). Silent
  truncation is therefore a plausible mechanism, but it is not proven.
* No single patient's final segments, and no pair of patients' final segments, match the surplus exactly.

## Data frozen as the P0 baseline

* Raw labels: 29,519 `.hea` and `.atr` files under `ESVEA_DATA` (not in git). Checksums:
  `results/p0_raw_MANIFEST.sha256`. Three listed segments have no `.atr` on PhysioNet:
  `results/p0_raw_MISSING.txt`.
* Environment: `results/p0_environment.txt` (Python 3.14.3, wfdb 4.3.1, full package list).
* Analysable rule, coded in `esvea.ingest.tables.is_analysable`: at least one non-Q beat. On P0 it
  excludes p08269 and p10564, which contain only Q beats.

## Decision

Proceed with today's data as the P0 baseline. The pipeline code and the G1 targets are unchanged. The
proposal and slides are not edited now. The supervisors will decide whether Table 4.2 is updated or the
new values are reported in the RO1 paper and thesis.

Later steps that compare with Table 4.2 (B1: "20% P0 row equals Table 4.2") will show the same
differences for the same reason; they are to be read against this note.
