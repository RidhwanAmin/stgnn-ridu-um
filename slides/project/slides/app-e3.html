Why: Icentia11k has the labels but none of the watch's losses; the model must learn from watch-like input with exact targets. RO4a later uses a separate degradation, sampled independently and adding pulse deficit and timing noise, so it is not tested on its own training losses.

Held for questions, if asked how a model trained on ECG can work on a watch. Icentia11k gives true labels for every beat but no flags, motion or gaps. The simulator adds them following the Garmin specification: beats in motion episodes are flagged, some are dropped without a flag at a rate set by π̂(m), and stretches are removed as gaps. The truth is kept alongside, so the training targets stay exact. Each rule is calibrated from work already done: the P0 filter results set the flag thresholds, the Pulsewatch pre-check showed the motion effect can be measured, and the clock-time check is why blocks are assigned at random on pseudo-days. Motion itself is the open choice D4: Icentia11k has no accelerometer, so motion episodes would be sampled from Pulsewatch. RO4a does not reuse this code; its degradation is sampled independently and adds pulse deficit and timing noise.
