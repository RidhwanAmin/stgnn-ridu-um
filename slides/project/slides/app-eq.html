Appendix: Retention-Weighted Daily Rate (Equations 3.1 to 3.4)

(3.1)   π̂(m) = P(beat reported | motion m, outside a gap)

(3.2)   R̂(d) = Σh (Lh/24) · [ Σi∈A(d,h) p̂i / π̂(mi) ] / τ(d,h)

(3.3)   report R̂(d) only if c(d, h) ≥ θblock for every block h

(3.4)   R̄ = Σh (Lh/24) · [ Σd∈V Σi∈A(d,h) p̂i / π̂(mi) ] / Σd∈V τ(d,h)

  • A(d,h): beats the device reports in day d, block h; p̂i: calibrated PAC probability; mi: motion; τ(d,h): observed hours. Gaps go to τ; the flag is an input and adds no weight
  • Blocks h: 00–06, 06–12, 12–18, 18–24 h (Lh = 6 h); θblock: per-block minimum fixed after device verification; V: valid days
  • Per-day values (3.2, 3.3) for stability; ESVEA from the pooled participant count 24 · R̄ (3.4); sensitivity: shrinkage towards Larsen et al. (2016), λ = 1 h (0.5 to 4 h)
  • Retention corrects only silent loss at motion: fitted on Pulsewatch (ECG R-peaks, PPG, accelerometer magnitude, per-session lag) outside peak-free stretches that mirror Garmin gaps; frozen. Pulse deficit leaves no beat to reweight, so it is a bias quantified in RO4a (Zheng et al., 2008)
  • 8-subject check: matching above chance at high motion and falling with motion, but retention depended on the detector (0.850 vs 0.752) → detector sensitivity analysis; primary detector: Elgendi et al. (2013) algorithm on all segments, authors' peaks as alternative

If asked how the quality flag is used rather than deleted: the Garmin keeps abnormally short or long beats with a low-confidence flag and marks a gap where it gives no beat (Garmin, 2023). Gaps enter the observed time; flagged beats stay in the model's input and are not reweighted, so no beat is corrected twice. Only beats lost silently at motion are corrected: each reported beat is weighted by the inverse of its retention probability, as in inverse-probability weighting, and the rate is normalised by observed time per block. Beat probabilities are temperature-scaled on validation subjects before they are summed, because a sum of uncalibrated probabilities inflates the count. Retention depends on motion only and is fitted on Pulsewatch, excluding stretches with no detected peak that mirror the Garmin gap rule, so loss the Garmin would mark as a gap is not corrected twice. If asked about a premature beat with no wrist pulse: it leaves no reported beat with a similar coupling interval, so weighting cannot restore it (a positivity failure); it is quantified as a bias by the RO4a pulse-deficit sweep, and a merged-interval output that predicts hidden PACs is possible RO2 work. The released alignment is not beat-accurate, so a lag is fitted per session; a lag method that does not need labelled segments is an RO2 task. The 8-subject check did not pass its locked rule: matching was above chance at high motion and fell with motion, but absolute retention differed by detector, so no retention value is claimed. Each block is weighted by its length, with no external profile. The gate refuses to report a daily count unless every 6-hour block meets the minimum; ESVEA status uses Equation 3.4, which pools each block across the participant's valid days, so a block thin on one day is informed by the same block on other days. A calibrated simulation showed pooling as accurate as shrinkage towards the published profile, and better than averaging only fully covered days when coverage is poor; a day can still count as valid wear for the RO3 feasibility outcome under the day and night rule.
