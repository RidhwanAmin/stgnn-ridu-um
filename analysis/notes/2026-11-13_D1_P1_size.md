# D1: size of P1 (written before P1 is drawn)

Date: 13 November 2026. Checklist A8; runbook T3. Generated by `scripts/s05_power_d1.py`.

## P0 fit

H1 model on P0 (20% threshold; PAC coupling intervals retained per patient; logit of retention on log PACs/h
with a patient random intercept; `esvea.ro1.glmm`), 275 patients with at least one PAC:

* b = 0.1239; Wald 95% CI 0.0563 to 0.1915 (SE 0.0345)
* profile-likelihood 95% CI 0.0566 to 0.1924
* a = -1.9620; sigma = 1.2733

## Power

500 simulations per cell, alpha 0.05, two-sided Wald test of b. Patients are resampled from P0 (log PACs/h
and interval count together) and retained counts drawn from the fitted model, with b set to the P0 estimate
or to half of it. Seeds: 2026 + size (P0 effect), 102026 + size (half effect).

| P1 size | power at P0 effect | power at half the P0 effect |
|---|---|---|
| 300 | 0.968 | 0.476 |
| 500 | 0.998 | 0.666 |
| 700 | 1.000 | 0.846 |
| 900 | 1.000 | 0.914 |
| 1100 | 1.000 | 0.940 |
| 1300 | 1.000 | 0.972 |
| 1500 | 1.000 | 0.984 |

Rule: smallest size with at least 0.90 power at HALF the P0 effect. **P1 size = 900.**

## False-positive check at the chosen size

True b = 0, size 900, 1000 simulations (seeds 202026 to 202045): rejection rate
0.040 (95% CI 0.029 to 0.054); consistent with the nominal 0.05.

Seed for drawing P1: to be recorded in `splits/P1.txt`. Run time 25 min.

Simulation precision: with 500 simulations, the power of 0.914 at size 900 has a Monte Carlo standard
error of about 0.013, so it is about one standard error above the 0.90 target.

## First run (13 November 2026): invalid and discarded

A first run of this script on the same P0 data, earlier on 13 November 2026, was invalid. Its table is
discarded and is not used for any decision.

* **False standard error.** The per-patient search for the random-effect mode in `glmm` (undamped
  Newton from u = 0) diverged for one patient, p01525 (97 of 123 PAC coupling intervals retained), just
  below the optimum. The likelihood jumped by about 10,500 there, the optimiser stopped on that edge,
  and the Wald SE of b came out as about 0.00002 (95% CI 0.114 to 0.115) instead of about 0.03. The
  simulated test therefore rejected far too often: the false-positive rate at true b = 0 was 0.58
  instead of 0.05, so the power figures measured mostly false positives.
* **Silent fallback.** No size in that run's grid (50 to 300) reached 0.90 at half the effect, and the
  script then reported the largest size, 300, as if the rule had chosen it.
* **Fix.** The mode search was replaced by a safeguarded search (commit 2bd3374, "glmm: safeguarded
  per-patient mode search; profile-likelihood CI for b"), with regression tests in
  `tests/test_glmm_safeguard.py`. This script now exits with an error when no size meets the rule, uses
  the grid 300 to 1,500, reports the profile CI beside the Wald CI, and checks the false-positive rate
  at the chosen size. The model, the rule and the P0 data are unchanged.
